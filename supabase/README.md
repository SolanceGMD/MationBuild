## One-time private secret setup

Key issuance and moderation require the server-side `MATIONBUILD_ADMIN_TOKEN`. The connected Supabase tool does not expose a secret-write operation, so this token has **not** been set by automation.

1. Open the [Supabase Function secrets page](https://supabase.com/dashboard/project/gfgmknlxzdfnjdpxetdz/functions/secrets).
2. Add `MATIONBUILD_ADMIN_TOKEN` with a long random secret generated by a password manager.
3. Add `ALLOWED_ORIGIN` with `https://solancegmd.github.io` (origin only, no path).
4. Never paste these values into chat or commit them to GitHub. Supabase provides the service-role credential to the function as a server-side environment variable; it must not be exposed in browser code.
5. After setting the secret, test one issuance from the private CLI below, save the returned key securely, then test verification and revocation.

## Private admin CLI

Requires Node.js 18+ and the token configured in your local shell. Run these commands from the repository root. Do not put the token in a command-line argument, source file, or shared shell history.

PowerShell:
```powershell
$env:MATIONBUILD_ADMIN_TOKEN = Read-Host "Paste admin token"
node scripts/mationbuild-admin.mjs pending
node scripts/mationbuild-admin.mjs issue "Creator access" 365
```

macOS/Linux:
```sh
read -s MATIONBUILD_ADMIN_TOKEN
export MATIONBUILD_ADMIN_TOKEN
node scripts/mationbuild-admin.mjs pending
node scripts/mationbuild-admin.mjs issue "Creator access" 365
```

Commands:
- `pending` — list template submissions waiting for review.
- `issue [label] [days]` — issue a license key (1–3650 days). The plaintext key is returned only once.
- `revoke MB-XXXXXX-XXXXXX-XXXXXX` — revoke a license key.
- `moderate <slug> publish|reject|remove` — approve or reject a submission, or remove a published template.

Do not run a CLI command on a shared machine. Clear the environment variable when finished. Key issuance/moderation will return `forbidden` until the server-side admin secret is configured.

## API actions

- `POST { "action": "verify", "key": "MB-..." }`
- `POST { "action": "issue", "label": "Creator", "days": 365 }` with `x-admin-token`
- `POST { "action": "revoke-key", "key": "MB-..." }` with `x-admin-token`
- `GET /templates` lists published templates
- `POST { "action": "submit-template", ...metadata }` creates a pending review entry
- `POST { "action": "list-pending-templates" }` with `x-admin-token`
- `POST { "action": "moderate-template", "slug": "...", "status": "published|rejected|removed" }` with `x-admin-token`

## Abuse protection and limitations

- Database-backed fixed-window rate limits: verification 20/minute per observed client address; submissions 5/hour; catalog reads 120/minute; admin actions are also throttled. The function fails closed if the rate-limit store is unavailable.
- The rate limiter hashes the observed address before storage. Proxy header behavior should be reviewed before relying on it as a hard anti-abuse boundary; consider adding a managed WAF/Turnstile if public traffic grows.
- Community submissions are metadata only and remain pending until reviewed. The importer must never execute arbitrary downloaded content.
- This is not yet a production-ready paid licensing service. There is no device binding or automated abuse monitoring. The browser verification endpoint is not equivalent to in-game key enforcement.
- Review Supabase security/performance advisors and monitor usage/billing before public launch.
